# Contributing

1. Read the architecture, governance, and relevant ADRs.
2. Keep changes scoped and explain their purpose.
3. Add or update tests for behavior changes.
4. Validate data at module boundaries.
5. Never commit secrets or real personal data.
6. Do not claim tests passed unless they were executed.
7. Preserve human-authored documentation and flag stale content rather than silently overwriting it.

Use descriptive commits. Changes affecting architecture require an ADR.
