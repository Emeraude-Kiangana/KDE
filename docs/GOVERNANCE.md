# KDE Governance

## #0$ operating rules

- Cost classes: prefer native, permanent-free, student, and free-tier resources. Unknown costs are disabled until verified.
- No implicit spend, paid API activation, or promotional-credit assumptions.
- No GitHub merge, release, or deployment without explicit human approval.
- No secrets in source, logs, screenshots, fixtures, or evidence bundles.
- Report only actions actually performed and results actually observed.

## Evidence states

- DOCUMENTED — written down, not necessarily implemented.
- IMPLEMENTED — code exists, not necessarily tested.
- TESTED — test execution evidence exists.
- REPRODUCIBLE — documented procedure succeeds in a clean equivalent environment.
- UNKNOWN — not established.
- BLOCKED — cannot proceed due to a recorded constraint.

## Claim discipline

A status must never be promoted without its corresponding evidence. A passing unit test does not prove production readiness, security, or reproducibility.
